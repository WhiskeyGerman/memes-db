## SLI и SLO

| Метрика | Что измеряет | SLI и SLO за 30 дней |
| --- | --- | --- |
| `memes_http_requests_total` | Counter завершённых HTTP-запросов. | Не менее 99,5% публичных запросов без 5xx. |
| `memes_http_request_duration_seconds` | Histogram длительности HTTP-запросов. | Не менее 99% публичных ответов не дольше 1 секунды. |
| `pg_up` | Gauge подключения postgres-exporter к БД: 0 или 1. | Не менее 99,9% хороших интервалов PostgreSQL. |
| `probe_success` | Gauge результата проверки ленты: 0 или 1. | Не менее 99,5% хороших интервалов пробера. |

Первые три метрики собраны в ДЗ 4, четвёртую добавляет пробер.
HTTP-показатели ограничены маршрутами `/v1/.*` в namespace `memes-db`.
Health-проверки, внутренние API и `/metrics` исключены. Ответы 4xx считаются
обработанными без серверного отказа. Гистограмма учитывает также ошибочные
ответы: быстрый 5xx ухудшает HTTP SLI, но может пройти критерий задержки.

## Расчёт доступности

Для окна `W` обозначим число публичных запросов как `N`, число ответов
5xx как `E`, число ответов не дольше секунды как `F`. Для задержки
`N` берётся из `_count` гистограммы, `F` из `_bucket{le="1.0"}`.

```text
HTTP_SLI(W) = 100 * (N - E) / N
Latency_SLI(W) = 100 * F / N
DB_SLI(W) = 100 * sum(DB_good(t)) / K
Feed_SLI(W) = 100 * sum(Probe_good(t)) / K
```

HTTP SLI и Latency SLI используют RBSLO. `sum(increase(...[W]))` учитывает
приросты и сбросы счётчиков каждого Pod. Без запросов SLI не определён.

Для TBSLO используются точки `t` с шагом 15 секунд, `K` - их количество
в окне. `DB_good(t)` и `Probe_good(t)` берут последнее значение `pg_up`
и `probe_success` за 30 секунд. Значение 1 означает хороший интервал,
0 или отсутствие свежего наблюдения - плохой. Пример расчёта для пробера:

```promql
100 * avg_over_time((min(last_over_time(probe_success{job="memes-db-probe",scenario="catalog-feed"}[30s])) or vector(0))[5m:15s])
```

Для PostgreSQL применяется та же формула к `pg_up{namespace="memes-db",job="postgres"}`.
Пропавший таргет остаётся плохим интервалом, а не исчезает из знаменателя.
SLO выполнен, если SLI за 30 дней не ниже соответствующего порога.

## SLA приложения

Сформулировал учебное SLA: чтение публичной ленты через Gateway доступно
не менее 99% времени за скользящие 30 дней.
Плановые работы учитываются. Браузер, внешняя сеть и остальные операции
приложения этим обязательством не покрываются.

```text
SLA выполнен, если Feed_SLI(30 дней) >= 99%
Бюджет отказов = 0,01 * 30 дней = 432 минуты = 7 часов 12 минут
Остаток бюджета, % = 100 * (Feed_SLI(W) - 99) / (100 - 99)
```

Бюджет - пересчёт того же SLI. SLO ленты 99,5% строже SLA 99%. SLA оценивается после полных 30 дней наблюдения.

## Пробер

Использовал готовый blackbox-exporter `v0.29.1`.
[Манифест и правила проверки](deploy/k8s/monitoring/blackbox.yaml).
Каждые 15 секунд vmagent вызывает его `/probe` с модулем `catalog_feed`.
Экспортёр обращается через Gateway к `GET /v1/media?limit=1`
с заголовком `Host: localhost`.

Проверка проходит при HTTP 200, JSON Content-Type и наличии полей `items`
с массивом, `next_before`, `next_before_id`. Таймаут - 5 секунд.
Пустая лента допустима. Проверяются регулярные выражения в ответе,
без полной валидации JSON и скачивания медиафайлов.

Экспортёр создаёт `probe_success`, vmagent добавляет `up`.
При отказе ленты возможны `up=1` и `probe_success=0`:
метрики получены, но пользовательский сценарий не работает.

## Изменения приложения

При отказе БД `/metrics` теперь продолжает отдавать HTTP 200 с техническими
метриками. `memes_metrics_dependency_available` становится 0, устаревшие
бизнес-Gauge убираются. После восстановления свежие значения снова читаются
из БД. Иначе ошибка зависимости скрывала технические показатели за HTTP 503.

## Проверка и демонстрация

```bat
kubectl -n monitoring get pods,svc
kubectl -n memes-db get pod postgres-0
```

Каждый port-forward запускается в отдельном терминале:

```shell
kubectl -n monitoring port-forward service/victoria-metrics 8428:8428
kubectl -n monitoring port-forward service/vmagent 8429:8429
kubectl -n envoy-gateway-system port-forward service/memes-db-gateway 5173:80
```

В [VMUI](http://127.0.0.1:8428/vmui/) открываем Dashboards, выбираем историю
Last 15 minutes и автообновление 10 секунд. На графиках показаны исходные
метрики, четыре SLI, линии SLO/SLA, выполнение порогов и бюджет ошибок.
[Таргеты vmagent](http://127.0.0.1:8429/targets) содержат четыре API,
postgres-exporter и пробер.

Для демонстрации используется окно 5 минут. Для месячного расчёта
`[5m]` и `[5m:15s]` заменяются на `[30d]` и `[30d:15s]`.
Короткий эксперимент не подтверждает соблюдение месячного SLA.

Проверил изменение поведения приложения:

| Воздействие | Результат |
| --- | --- |
| Отзыв SELECT у Catalog | HTTP 503, снижение HTTP SLI и SLI ленты; PostgreSQL доступен. |
| Блокировка таблицы на 4 секунды | Медленные HTTP 200, снижение Latency SLI. |
| Восстановление ресурсов | Успешные запросы; после выхода отказов из окна SLI возвращаются к 100%. |
